## 2. Метрики Performance и их вес

| Метрика | Что показывает | Вес |
| --- | --- | --- |
| FCP (First Contentful Paint) | время до первого текста или картинки | 10 % |
| LCP (Largest Contentful Paint) | время до самого крупного элемента | 25 % |
| TBT (Total Blocking Time) | сколько занят основной поток | 30 % |
| CLS (Cumulative Layout Shift) | насколько сдвигаются элементы | 25 % |
| SI (Speed Index) | насколько быстро страница визуально заполняется | 10 % |

Главные при приоритизации — TBT, LCP и CLS: у них наибольший вес.

## 4. Найденные проблемы

| № | Проблема | Страница | Метрика/категория | Аудит Lighthouse |
| --- | --- | --- | --- | --- |
| 1 | Ссылка на мастера выделена только цветом | `/uslugi/zashchitnye-obryady` | Accessibility, 96 | `link-in-text-block` |
| 2 | Изображения отдаются в JPEG вместо WebP | все, где есть картинки | Performance, Best Practices | `modern-image-formats` |
| 3 | Статика и шрифты кешируются 30 дней вместо года | все | Best Practices (0,5) | `uses-long-cache-ttl` |
| 4 | Дублирование заголовка `X-Robots-Tag` на API | `/api/*` | SEO/инфраструктура | проверено вручную в Network |

## 5. Приоритизация

Влияние на пользователя × трудоёмкость исправления.

| Приоритет | Проблема | Влияние | Сложность | Как исправить |
| --- | --- | --- | --- | --- |
| Высокий | 1. Ссылка только цветом | доступность: ссылку не видно без различения цвета | низкая | добавить `underline` к ссылке |
| Высокий | 2. JPEG вместо WebP | вес страницы, LCP | средняя | перевести картинки в WebP (Pillow), обновить пути |
| Средний | 3. Кеш 30 дней | повторные заходы | низкая | `expires 1y` + `Cache-Control: immutable` |
| Низкий | 4. Дубль `X-Robots-Tag` | формально не ошибка | низкая | `proxy_hide_header` в nginx |

Проблемы с высоким приоритетом исправлены и подтверждены повторным замером.

## 9. PageSpeed Insights

`pagespeed.web.dev` принимает только публичные адреса. Проект по 152-ФЗ не публикуется, поэтому
проверить его в PSI нельзя: локальный `https://doska.localhost` сервис не откроет. Полевых данных
(CrUX) у проекта тоже нет. В отчёте это зафиксировано как ограничение, лабораторные замеры сделаны
локально в Lighthouse на той же продакшен-сборке.

## 10. Сравнение с сайтом-аналогом

Аналог: **magic-online.ru** (реальный сайт эзотерических услуг, один из трёх аналогов из отчёта
по подготовке к разработке). Прогон в Lighthouse с теми же настройками (Desktop, 4 категории,
1 запуск).

| Показатель | Наш проект | magic-online.ru |
| --- | --- | --- |
| Performance | 100 | 86 |
| Accessibility | 100 | 83 |
| Best Practices | 100 | 78 |
| SEO | 100 | 100 |
| FCP | 241 мс | 1 063 мс |
| LCP | 382 мс | 1 578 мс |
| TBT | 0 мс | 0 мс |
| CLS | 0,000 | 0,027 |
| Speed Index | 241 мс | 2 903 мс |

Выводы:

1. Наш проект быстрее по всем метрикам: LCP меньше в 4 раза, Speed Index — в 12 раз. Причина —
   статическая сборка без сторонних скриптов и локальные шрифты вместо подключения внешних сервисов.
2. Аналог проигрывает по доступности (83): там есть проблемы с контрастом и подписями к полям.
3. По SEO оба сайта на 100 — базовая разметка у аналога в порядке, но по скорости и доступности
   наш проект заметно лучше.

## 12. Вывод

Аудит проведён на продакшен-сборке: проверены все публичные страницы (3 запуска, медиана),
служебные страницы с `noindex` и страница, требующая входа. Найдены четыре проблемы, две из них
с высоким приоритетом — исправлены и подтверждены повторным замером: доступность карточки услуги
выросла с 96 до 100, изображения переведены в WebP, кеш статики увеличен до года. Все публичные
страницы имеют 100 баллов по четырём категориям Lighthouse, Core Web Vitals в зелёной зоне.
По сравнению с реальным аналогом проект быстрее и доступнее при равной оценке SEO.
