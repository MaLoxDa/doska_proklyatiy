## 2. Базовые метатеги

Что сделано (пункт 1 задания и «Основные метатеги», стр. 26):

- `<html lang="ru">` — атрибут на всех страницах (задаётся один раз в корневом layout);
- `<meta charset="UTF-8">` — первым в `<head>` (Next.js выводит его автоматически, порядок проверен по `view-source`);
- `<meta name="viewport" content="width=device-width, initial-scale=1">` — через `viewport` в Next.js;
- `title` — уникальный на каждой странице, по шаблону «Страница — Доска проклятий»;
- `description` — уникальный, 1–2 содержательных предложения, без перечисления ключевых слов;
- `meta keywords` **не добавлен** — Google его не использует;
- `canonical` — на каждой странице, абсолютный адрес (нужен, потому что страницы доступны и с `/`, и без);
- Open Graph (`og:title`, `og:description`, `og:image`, `og:url`) — на главной и карточках.

## 3. Структура заголовков

- На каждой странице **ровно один `<h1>`**: на главной — «Ритуалы и консультации», в каталоге — «Услуги»,
  в карточке услуги — название услуги, у мастера — имя мастера.
- Дальше только `<h2>` и `<h3>` без пропусков уровней: блоки страницы — `h2`, карточки внутри — `h3`.
- Текст, который выглядит заголовком, но был свёрстан через `<div>`/`<span>`, заменён на настоящие
  заголовки нужного уровня (например, строки каталога услуг и имена мастеров).
- Блок «Как заказать» переделан: раньше заголовки шагов были `<h4>` сразу после `<h1>`, теперь это `<h2>`
  и элементы списка.

## 4. robots.txt

Файл собирается приложением и попадает в сборку (`frontend/out/robots.txt`), открывается по адресу
`https://doska.localhost/robots.txt` с кодом 200.

```
User-Agent: *
Allow: /
Disallow: /moi-zakazy
Disallow: /api/

Host: https://doska.localhost
Sitemap: https://doska.localhost/sitemap.xml
```

- `Allow: /` открывает весь сайт, `Disallow` закрывает личный кабинет и ответы API;
- личный кабинет дополнительно требует авторизации, а не только закрыт в `robots.txt`;
- `Sitemap:` указан и файл существует (иначе директиву ставить нельзя);
- устаревшие `Crawl-delay` не добавлялись; кириллицы в путях нет.
- Для API дополнительно отдаётся заголовок `X-Robots-Tag: noindex, nofollow` (см. пункт 6).

## 5. sitemap.xml

Файл собирается приложением (`frontend/out/sitemap.xml`), открывается по адресу
`https://doska.localhost/sitemap.xml` с кодом 200, содержит **13 абсолютных URL**:

`/`, `/uslugi/`, `/uslugi/lyubovnaya-magiya/`, `/uslugi/denezhnye-ritualy/`, `/uslugi/zashchitnye-obryady/`,
`/uslugi/snyatie-proklyatiy/`, `/uslugi/konsultaciya-po-taro/`, `/uslugi/amulet-obereg/`, `/mastera/`,
`/mastera/mariya/`, `/mastera/aleksey/`, `/mastera/elena/`, `/zayavka/`.

В карту не попали страницы с `noindex` (`/vhod`, `/moi-zakazy`, `/zayavka/otpravleno`, страница 404)
и служебные адреса `/api/`. Все адреса абсолютные и отдают код 200.

## 6. Директивы индексации

| Страница | Директива | Почему |
| --- | --- | --- |
| `/vhod` | `<meta name="robots" content="noindex, nofollow">` | страница входа не должна попадать в поиск |
| `/moi-zakazy` | `noindex, nofollow` + `Disallow` в robots.txt | личные заказы пользователя |
| `/zayavka/otpravleno` | `noindex, nofollow` | техническая страница подтверждения |
| страница 404 | `noindex, nofollow` | служебная страница |
| `/api/*` | заголовок `X-Robots-Tag: noindex, nofollow` | ответы API не индексируются |

Важно: страницы, которые нужно убрать из поиска, не закрыты одновременно в `robots.txt` и `noindex`
(это противоречие из методички): `/vhod` только с `noindex`, `/moi-zakazy` — с `Disallow` **и** `noindex`,
потому что доступ к нему требует входа, а поисковик без авторизации увидит редирект.

## 7. Внутренняя оптимизация

- **Понятные URL**: `/uslugi/zashchitnye-obryady` вместо `?id=123`.
- **alt у изображений**: содержательный у смысловых картинок («Иллюстрация к услуге «Защитные обряды»…»,
  «Фотография мастера Мария») и `alt=""` у декоративного фона hero, чтобы скринридер его пропускал.
- **Внутренние ссылки** — только `<a href>` / `Link`: перехода по `onClick` на `<div>` нет.
- **canonical** — на всех страницах, в исходном HTML (не подставляется скриптом).
- **Коды ответов**: несуществующая страница отдаёт 404, HTTP → HTTPS — 301, `/robots.txt`, `/sitemap.xml` — 200.

## 9. Как проверить самому

1. `docker compose up --build -d` в папке `doska-proklyatiy-deploy/`.
2. Открыть `https://doska.localhost/robots.txt` и `https://doska.localhost/sitemap.xml` — должны открываться,
   а не показывать главную и не давать 404.
3. `Ctrl+U` на главной: `lang`, `charset`, `viewport`, `title`, `description`, `canonical` должны быть
   в исходном HTML, а не появляться только после выполнения JS (сверить с вкладкой Elements).
4. F12 → Lighthouse → Desktop → Analyze page load; повторить на `/uslugi` и карточке услуги.
5. DevTools → Network → запрос `/api/services`: в заголовках ответа `x-robots-tag: noindex, nofollow`.

## 10. Ограничения

- Lighthouse не проверяет смысловую уникальность `description` — это проверено вручную по таблице из пункта 2.
- `error-in-console` в отчёте «до» связан с битой вёрсткой старой страницы; после переписывания на компоненты
  ошибок в консоли нет.
- Аналитика (Яндекс Метрика, Google Analytics) не подключалась: проект не публикуется в интернет и содержит
  данные пользователей (152-ФЗ), передавать их внешним сервисам нельзя.
